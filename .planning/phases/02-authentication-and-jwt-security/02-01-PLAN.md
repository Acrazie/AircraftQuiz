Append to `findings/02-01-lexik-gesdinet.md` the Gesdinet section.

Read `gesdinet_jwt_refresh_token.yaml` and document these findings:

**Finding 1 — Missing `single_use` (SEC-14):**
- File: `server/config/packages/gesdinet_jwt_refresh_token.yaml`
- The `single_use` key is ABSENT from the config. Gesdinet defaults to `false` when omitted.
- Impact: A stolen refresh token can be exchanged unlimited times over its 30-day window. There is no token rotation — the same refresh_token string persists for its full TTL. An attacker with a single captured refresh token has persistent 30-day access.
- Severity: HIGH
- Remediation snippet: Add `single_use: true` to the yaml config
- Addresses: C-08 (partial — rotation aspect)

**Finding 2 — Excessive refresh token TTL:**
- File: `server/config/packages/gesdinet_jwt_refresh_token.yaml`
- `ttl: 2592000` = 30 days. Combined with `ttl_update: true`, each successful refresh extends the window by another 30 days, creating an effectively infinite session for active users.
- Severity: MEDIUM
- Remediation: Reduce to 604800 (7 days); consider whether `ttl_update: true` is appropriate for a game application
- Addresses: C-08 (partial — TTL aspect), C-09 (partial — validation TTL)

**Finding 3 (informational) — `user_identity_field: email`:**
- Both Lexik and Gesdinet use `email` as user identity. This means username changes do not affect token validity, but email changes would. Document as informational note.
