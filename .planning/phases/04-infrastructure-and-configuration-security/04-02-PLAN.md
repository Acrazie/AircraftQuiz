   - `server/.env.prod.example` — verify it contains only placeholder/template values
   - Check if any `.env.local` or `.env.prod` files are tracked: `git ls-files server/.env*`

2. Scan full git history for committed secrets:
   ```bash
   # Search for secret-shaped values in all commits
   git log --all -p -- '*.env*' | grep -iE '(PASSWORD|SECRET|PRIVATE_KEY|API_KEY|TOKEN|CREDENTIAL)' | grep -v '^[+-]#' | head -50
   ```
   ```bash
   # Check if .env.local was ever committed
   git log --all --diff-filter=A -- 'server/.env.local' 'server/.env.prod' '.env.local'
   ```
   ```bash
   # Search for JWT private key material in history
   git log --all -p | grep -E '(BEGIN (RSA |EC )?PRIVATE KEY|jwt_private|JWT_PRIVATE)' | head -20
   ```
   ```bash
   # Search for database credentials
   git log --all -p | grep -iE '(DB_PASSWORD|DATABASE_URL.*:.*@|POSTGRES_PASSWORD)' | grep -v 'placeholder\|example\|changeme\|your_' | head -20
   ```
   ```bash
   # Search for Google OAuth secret
   git log --all -p | grep -iE 'GOOGLE_CLIENT_SECRET' | grep -v 'placeholder\|example\|your_' | head -20
   ```
   ```bash
   # Search for R2/AWS credentials
   git log --all -p | grep -iE '(AWS_SECRET_ACCESS_KEY|R2_SECRET_ACCESS_KEY)' | grep -v 'placeholder\|example\|your_' | head -20
   ```

   - Public URLs

  <action>
Append HTTP security headers audit to the existing findings file.

1. Read `nginx/security_headers.conf` and document all present headers:
   - X-Frame-Options: SAMEORIGIN (present — CLEAN)
   - X-Content-Type-Options: nosniff (present — CLEAN)
   - X-XSS-Protection (present — document value)
   - Referrer-Policy (present — document value)
   - Permissions-Policy (present — document value)

2. Flag missing headers:
   - **Content-Security-Policy (CSP)**: ABSENT — raise as HIGH finding
     - Impact: No CSP means inline scripts, eval(), and arbitrary external script loading are unrestricted; XSS payloads execute without browser-level mitigation
     - Connects to GAP-02 from Phase 1 trust boundary map
     - Remediation: provide a starter CSP policy for the application:
       ```
       Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' https://*.r2.cloudflarestorage.com data:; connect-src 'self'; font-src 'self'; frame-ancestors 'none';
       ```
     - Note: `'unsafe-inline'` for style-src needed for Tailwind; frame-ancestors 'none' replaces X-Frame-Options

   - **Strict-Transport-Security (HSTS)**: ABSENT — raise as MEDIUM finding
     - Impact: Without HSTS, first-visit HTTP connections are vulnerable to SSL stripping; no HSTS preload submission possible
     - Connects to GAP-03 from Phase 1 trust boundary map
     - Remediation: `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`

3. Audit profiler route exposure in nginx.conf:
   - Read the `_profiler` and `_wdt` location blocks (lines ~112-116)
   - Document that these routes are proxied to Symfony unconditionally — no APP_ENV guard at nginx layer
   - The "remove in production" comment proves developer awareness but not enforcement
   - Connects to GAP-01 from Phase 1 trust boundary map
   - Score as:
     - Current state (APP_ENV=dev): LOW risk — profiler intended for development
     - If deployed to production without removing: HIGH risk — profiler exposes route details, DB queries, request data, environment variables
   - Raise as MEDIUM finding with dual-context severity narrative
   - Remediation: either remove profiler block in production nginx config, or add environment-conditional include

4. Write findings with standard format:
   - SEC-F-NNN for CSP absence (HIGH)
   - SEC-F-NNN for HSTS absence (MEDIUM)
   - SEC-F-NNN for profiler route exposure (MEDIUM with dual-context)
   - Each with: file:line evidence, code snippet (3-8 lines), impact narrative, remediation snippet
  </action>
