Known findings from research (confirm and document with full evidence):

1. **No skeleton screens anywhere** (MEDIUM per calibration):
   - All loading states use `loading-spinner` or `loading-dots` — no `skeleton` class usage
   - List every loading state location and its spinner variant
   - Note DaisyUI v5 provides `skeleton` class but it is unused
   - Impact: Content layout shift when data loads; spinner shows no preview of content structure

2. **AirCraftQuiz error state inconsistency** (LOW):
   - AirCraftQuiz.jsx uses `<p className="text-error">` instead of `<div className="alert alert-error">`
   - All other error states use DaisyUI alert component
   - Impact: Inconsistent error severity signaling; text-error lacks the visual container of alert-error

3. **Error vs warning severity inconsistency** (LOW):
   - Profile.jsx uses `alert-warning` for leaderboard fetch failure but `alert-error` for avatar upload failure
   - Document each error display and its DaisyUI variant
   - Assess whether the severity mapping (warning vs error) matches the actual failure severity

4. **ErrorBoundary limited user feedback** (LOW):
   - ErrorBoundary.jsx uses `console.error` only, no error ID visible to user
   - Generic reload button without contextual error information
   - Cross-refs: note this connects to maintainability (no remote error tracking)
